# 閱讀與自然拼讀—前測

家長從報名到看到結果，全程在線上自助完成：

1. 家長在介紹頁（網站首頁）了解測驗，按「免費報名」到報名頁填資料。
2. 系統自動產生孩子專屬的代碼，把測驗連結寄到家長的 Email。
3. 家長點信裡的連結（等於驗證了 Email），孩子作答，約 12 分鐘。
4. 做完立刻看到結果，並可以預約諮詢。之後用同一個連結可以再看結果。

免費。每位孩子只能測一次；要重測由你在試算表手動開放。

做法和 ORF 測驗相同，但兩者完全獨立：這個測驗有自己的 GitHub repo、Netlify 網站、Google 試算表和 Apps Script，不共用名單、成績或任何設定。不需要伺服器端函式，也不需要任何 API 金鑰。

## 部署步驟

網站要先有網址，Apps Script 才能把正確的連結寄給家長，所以順序是：先上網站，再設後端，最後把後端網址填回網站。

### 1. 上傳到 GitHub、接上 Netlify

1. 在 GitHub 建立新的 repo，把這個資料夾的全部內容上傳（`netlify.toml` 要在最上層）。
2. 在 Netlify 選「Add new site → Import an existing project」，選這個 repo。發佈目錄已經在 `netlify.toml` 設定為 `site`。
3. 記下網站的網址。要用自己的網域，先在 Netlify 設定好再進行下一步。

這時打開網站會看到「網站還沒有完成設定」，是正常的。

### 2. 建立試算表、部署 Apps Script

1. 建立一份新的空白 Google 試算表。不用建任何分頁，程式會自動建立。
2. 「擴充功能 → Apps Script」，刪掉預設內容，貼上 `Code.gs` 全部內容。
3. 修改最上面的三項設定：
   - `SITE_URL`：第 1 步的網站網址，例如 `https://gate.example.com/`。
   - `SENDER_NAME`：信件上顯示的寄件人名稱。
   - `NOTIFY_EMAIL`：有孩子完成測驗時要通知的信箱，不需要通知就留空。
4. 在編輯器上方的函式選單選 `setup`，按「執行」。第一次會要求授權，包含「寄送電子郵件」的權限。出現「Google 尚未驗證這個應用程式」時，按「進階 → 前往（專案名稱）→ 允許」。
5. 「部署 → 新增部署作業」，類型選「網頁應用程式」，執行身分「我」，存取權「所有人」。複製結尾是 `/exec` 的網址。

信是從你這個 Google 帳號寄出的，家長回信也會回到這個帳號。

### 3. 填寫網站設定

打開 `site/config.js`：

- `SHEET_API`：填第 2 步的 `/exec` 網址。
- `BOOKING_URL`：結果頁「預約諮詢」按鈕要連到的網址。
- `CONTACT_EMAIL`：顯示在頁面上的聯絡信箱。
- `REGISTRATION_OPEN`：先維持 `false`。
- `ALLOW_INCOMPLETE_ASSETS`：測試期間先改成 `true`。

上傳到 GitHub，Netlify 會自動重新發佈。

### 設定檢查頁

任何時候覺得設定有問題，打開「網站網址加上 `?check=1`」。這一頁會逐項檢查並說明怎麼修：`config.js` 有沒有載入、`SHEET_API` 的格式、後端連不連得上、後端是不是最新版、`SITE_URL` 有沒有填好、報名是否開放、圖片和錄音齊了幾個。

幾個常見的狀況：

- **`config.js` 沒有載入**：用「文字編輯」修改時，引號可能被自動改成彎引號（“ ”），整個檔案就會失效。請改用純文字模式，或直接在 GitHub 網頁上點鉛筆圖示編輯。
- **連不上後端**：部署時「誰可以存取」要選「所有人」。
- **後端是舊版**：改了 `Code.gs` 之後，要到「部署 → 管理部署作業 → 編輯 → 新版本」。按「新增部署作業」會產生另一個網址，原本的網址仍然執行舊程式。

### 4. 自己走一遍

1. 打開「網站網址加上 `?preview=1`」。還沒開放報名時，這樣才看得到報名表單。
2. 用自己的 Email 報名，到信箱收信，點連結，做完測驗。
3. 確認試算表：`gate_students` 有一列報名資料，`gate_summary` 有一列成績，`gate_responses` 有 74 列。
4. 再點一次信裡的連結，應該直接顯示結果，不能再測。
5. 測完把試算表裡測試用的列刪掉。

### 5. 正式開放

圖片和錄音都放齊之後（上傳前在本機執行 `python3 workflow/check_assets.py` 檢查）：

1. `ALLOW_INCOMPLETE_ASSETS` 改回 `false`。
2. `REGISTRATION_OPEN` 改成 `true`。
3. 上傳。之後學習地圖連到這個網站的根網址（介紹頁）即可。

介紹頁和報名頁的分工：介紹頁說明測驗的目的和題型，報名頁只放報名表。信裡的測驗連結是 `網站/?t=代碼`，介紹頁會自動轉到 `apply.html?t=代碼`；`?check=1`、`?preview=1`、`?demo=1` 也一樣會轉過去。所以 `Code.gs` 的 `SITE_URL` 維持網站根網址，不要改成 apply.html。

介紹頁上的例子是示意題，刻意不用正式題目裡的字，避免孩子先看過答案。

## 老師檢閱頁

網址是「網站網址/teacher.html」，例如 `https://pre-phonics-test.netlify.app/teacher.html`。用密碼登入後可以：

- 看所有報名的孩子：完成時間、結果、各部分題數（綠色達到建議起點、黃色接近、紅色未達），也看得到報名了但還沒做完的孩子。可以用名字、代碼或 Email 搜尋。
- 點一位孩子，看逐題作答：每一題孩子選了哪張圖（紅框）、正確答案是哪張（綠框）、錯誤類型、反應時間、重聽次數，並可以播放孩子當時聽到的聲音。預設只列答錯的題目，也可以切換成全部 74 題。
- 孩子重測過時，可以切換看每一次的作答。
- 用瀏覽器的列印功能存成 PDF。

開啟方式：在 Apps Script 的 `Code.gs` 最上面設定 `ADMIN_PASSWORD`（10 個字以上、不容易猜），儲存後以「管理部署作業 → 編輯 → 新版本」部署。沒設定密碼時，檢閱頁不能使用。

密碼只保存在瀏覽器的這個分頁，關掉分頁就要重新輸入。密碼連續錯 10 次會鎖 15 分鐘。這一頁會顯示家長的姓名和 Email，請不要把密碼給其他人。

## 日常管理

所有管理都在試算表裡做。

| 要做的事 | 做法 |
|---|---|
| 看誰報名、進行到哪一步 | `gate_students` 分頁：`registered_at` 報名、`verified_at` 點了連結、`started_at` 開始作答；有沒有完成看 `gate_summary` |
| 開放某個孩子重測 | 在 `gate_students` 該列的 `allow_retake` 欄填 `Y`。孩子用原本的連結就能再測一次，測完這一欄會自動清空 |
| 家長說沒收到信 | 請他在報名頁用同樣的 Email 和孩子名字再報名一次，系統會重寄原本的連結，不會產生新的代碼 |
| 信沒寄出去（`mail_status` 是 `quota` 或 `failed`） | 在 Apps Script 編輯器執行 `resendUnsent` |
| 刪除某位家長的資料 | 刪掉三個分頁裡該代碼的所有列 |
| 手動加入學生（不經過報名） | 在 `gate_students` 新增一列，填 `token`（自訂，全大寫）和 `child_name`，把「網站網址?t=代碼」交給家長 |

### 寄信額度

信是用你的 Google 帳號寄的，Google 對每天能寄的數量有上限：一般 Gmail 帳號每天約 100 封，Google Workspace 帳號約 1,500 封，實際數字以 Google 的公告為準。每一次報名、每一次重寄、每一封完成通知都算一封。執行 `setup` 可以在執行紀錄裡看到今天還能寄幾封。

額度用完時，報名資料仍然會存下來，家長會看到「連結會盡快補寄到您的信箱」。補寄不是自動的：隔天請你執行一次 `resendUnsent`。設了 `NOTIFY_EMAIL` 也不會收到額度用完的通知，所以報名量大的時候請留意 `mail_status` 欄。報名量會超過額度的話，需要改用 Workspace 帳號或專門的寄信服務。

### 防止濫用

- 同一個信箱每小時最多寄 3 封。
- 家長填的名字會去掉網址和換行、限制 20 個字，避免有人利用報名表單，以你的名義寄出廣告或釣魚信。
- 信裡的連結一律由 `Code.gs` 的 `SITE_URL` 產生，不採用網頁端送來的網址。
- 表單裡有一個隱藏欄位，自動填表的機器人填了它，報名就不會被處理。

### 個資

報名表單會收集家長的稱呼、Email、LINE 或 Facebook ID（選填）、孩子的名字或暱稱、年齡，資料存在你的 Google 試算表。表單上有一句必勾的同意文字和一個可不勾的行銷同意，文字在 `site/apply.html` 的報名表單區。這些文字是我寫的草稿，請依你的實際用途和個資法的告知要求確認後再開放報名。`marketing_ok` 欄是 `Y` 的家長才有同意收到課程資訊。

## 試算表的分頁

`gate_students` 每個孩子一列：代碼、孩子名字、年齡、家長稱呼、Email、接觸英文的情況、是否同意行銷、報名時間、寄信狀態、驗證時間、開始作答時間、開始次數、是否開放重測、備註、LINE 或 Facebook ID（選填）。

程式新增欄位時，舊的分頁會自動在最後面補上新欄位，原有資料不會移動。

`gate_summary` 每次施測一列：代碼、名字、第幾次、開始與完成時間、五個分測驗的答對題數、判讀結果、家長看到的結論代號、是否接近門檻、練習題答錯次數、素材是否齊全、題庫版本、裝置。

`gate_responses` 每題一列：題號、分測驗、題目、孩子的選擇、是否答對、錯誤類型、反應時間（毫秒）、重聽次數、對比類別或層級。

各分測驗的答對題數由 Apps Script 依作答紀錄重新加總。同一次施測重複送出只會記錄一次。`attempt_id` 是「代碼|開始時間」，可以用來把分頁對起來。

`started_at` 有值但 `gate_summary` 沒有成績的孩子，是開始了但沒做完。中途離開的孩子 12 小時內可以在同一台裝置接續；超過之後會從頭開始，仍然只算一次。

## 作答時的保護

| 情況 | 處理 |
|---|---|
| 圖片或錄音不齊全 | 不能作答，家長看到「測驗還在準備中」（除非打開 `ALLOW_INCOMPLETE_ASSETS`） |
| 中途重新整理或暫停 | 12 小時內在同一台裝置可以從下一題接續 |
| 成績送不出去 | 成績留在裝置上，可以按「再送一次」；重開連結會先補送，不會讓孩子重測 |
| 已經測過 | 連結只顯示結果，換裝置也一樣 |

試用版不對外公開，網址後面加 `?demo=1` 才會出現入口。試用版不儲存成績，素材不齊時以文字和瀏覽器語音代替。再加上 `&debug=1`，畫面會顯示每題的題目文字和選項角色，結果頁也會多出「細項」區塊。

## 家長看到的結果

做完測驗後，結果頁依序顯示：

1. **一句結論和說明**：依判讀結果顯示，例如「可以開始 Phonics 第一階段，同時持續累積聽力」。分數接近建議起點時，會加一句「差距在測驗的誤差範圍內。建議預約諮詢，由老師確認」。
2. **預約諮詢按鈕**：連到 `config.js` 的 `BOOKING_URL`；沒有填網址就不顯示。
3. **各部分的結果**：五種題型的答對題數、長條和狀態，分成「聽得懂的基礎」和「解碼的地基」兩組。不顯示每一題的對錯。
4. **這個測驗在看什麼**：用閱讀簡單觀點（解碼 × 語言理解）說明測驗的範圍和限制。

狀態有三級：達到建議起點是「準備好了」；差距在 2 題以內（8 題的題型為 1 題以內）是「接近」；其餘是「還需要累積」。對照詞和「相同」題是用來確認作答方式的，狀態寫成「沒問題／接近／需要確認」。

每一題的作答、錯誤類型和反應時間只寫進試算表，家長看不到。測完之後，家長用信裡的同一個連結可以再看這份結果。

家長看到的文字都在 `site/apply.html` 的 `PARENT`、`BORDER`、`NEXT`、`BORDER_BOOK`、`TYPES` 幾處，可以直接修改。`NEXT` 是每種判讀結論的「下一步可以做什麼」建議和按鈕上方的那句話；分數接近起點時，按鈕上方改用 `BORDER_BOOK`。

結果頁的「預約諮詢」按鈕連到 `site/config.js` 的 `BOOKING_URL`。留空就不顯示按鈕，建議仍會顯示。試算表 `profile` 欄記錄的仍是原本的判讀名稱（例如「A、B 達標；C 未達標」）。

## 錄音檔

清單在 `workflow/audio-manifest.csv`，共 89 個檔案，放在 `site/assets/audio/`。

| 用途 | 檔名 | 數量 |
|---|---|---|
| 單詞 | `w_<單字>.mp3` | 57 |
| 「相同」題的第二次錄音 | `w_<單字>_2.mp3` | 10 |
| 句子 | `<題號小寫>.mp3`，例如 `c01.mp3`；練習題是 `pc1.mp3` | 19 |
| 中文說明 | `inst_a.mp3`、`inst_b.mp3`、`inst_c.mp3` | 3 |

### 用語音合成產生

`workflow/make_audio.py` 用 OpenAI 的語音合成（`gpt-4o-mini-tts`）一次產生全部檔案。需要一把 OpenAI API 金鑰，金鑰只在執行時輸入，不會寫進任何檔案。

1. 打開「終端機」，輸入 `cd`、空一格，把專案資料夾拖進終端機視窗，按 Enter。
2. 輸入 `python3 workflow/make_audio.py`，按 Enter。第一次執行時，Mac 可能會要求安裝「開發者工具」，按安裝，裝好再執行一次。
3. 依提示貼上金鑰（畫面上不會顯示），按 Enter。89 個檔案約需幾分鐘。
4. 用瀏覽器打開 `workflow/review.html`，到「錄音試聽」分頁。第二部分的每一組按「▶ 整組」，會照測驗的順序連續播放兩個詞。
5. 按「▶ 全部依序播放」可以一次聽完全部 89 個。按「自動檢查音量」會找出幾乎沒有聲音、太短或太長的檔案。自動檢查需要用本機伺服器打開這一頁：在專案資料夾的終端機執行 `python3 -m http.server`，再用瀏覽器打開 `http://localhost:8000/workflow/review.html`（用完按 Control+C 關掉）。上線後，`?check=1` 設定檢查頁也會做同樣的檢查。
6. 聽不清楚的檔案按「標記重做」並寫原因，按「下載重做清單」，把 `redo-list.csv` 放進 `workflow/`，再執行：

```
python3 workflow/make_audio.py --redo workflow/redo-list.csv
```

其他用法：

| 指令 | 作用 |
|---|---|
| `python3 workflow/make_audio.py` | 只產生還沒有的檔案 |
| `python3 workflow/make_audio.py --only w_bed w_bad` | 只重做指定的檔案 |
| `python3 workflow/make_audio.py --voice cedar` | 換一個聲音（預設 `marin`；也可以試 `coral`、`sage` 等） |
| `python3 workflow/make_audio.py --force` | 全部重做，例如換了聲音之後 |
| `python3 workflow/make_audio.py --list` | 只列出會產生哪些檔案，不呼叫 API |
| `python3 workflow/make_audio.py --workers 1` | 一次只產生一個。出現很多「HTTP 429」時使用 |

每個檔案正常只要幾秒，畫面上會顯示每個檔案花了多久；遇到重試會寫出原因。按 Control+C 可以隨時中斷，已完成的檔案會保留，再執行一次會從缺的開始。

全部 89 個檔案最好用同一個聲音。換聲音時請加 `--force` 全部重做。朗讀的語氣指示寫在 `make_audio.py` 開頭的 `STYLE`，要調整可以直接改。

合成語音要特別注意兩件事：

- **第二部分的詞對**：每一組只差一個音，例如 bed／bad、thin／thing、think／sink。合成語音要把差別念清楚，否則測的是合成品質，不是孩子的聽辨能力。
- **「相同」題的第二次錄音**：腳本會另外呼叫一次，所以兩次聲音會有些微不同。如果聽起來和第一次完全一樣，或反而不像同一個詞，請重做。

### 改用真人錄音

只要檔名相同，直接覆蓋 `site/assets/audio/` 裡的檔案即可，程式不用改。錄音注意事項：

- 全部由同一個人、用同樣的音量和語速錄。
- 單詞用自然的語調念，不要為了讓孩子聽清楚而誇大某個音，否則音韻區辨測驗會失真。
- 第二次錄音必須是另外錄的一次，不能複製第一次的檔案。
- 每個檔案前後各留約 0.2 秒的靜音，檔名全小寫。

也可以只把第二部分的單詞換成真人錄音，其他保留合成語音。

## 圖片工作流程

1. 在 GPT Work 開啟這個資料夾，貼上：「請閱讀 workflow/IMAGE_BRIEF.md，先只做第 0 批的 8 張圖。做完執行檢查腳本，然後停下來等我核可。」
2. 用瀏覽器開啟 `workflow/review.html` 檢查。這一頁是本機工具，不會發佈到網站。
3. 不滿意的圖在檢查頁點一下、寫原因，按「下載重做清單」，把 `redo-list.csv` 放進 `workflow/`，請 GPT Work 處理。
4. 圖片齊全後上傳到 GitHub 的 `site/assets/images/`。GitHub 網頁一次最多上傳 100 個檔案，187 張要分兩次；也可以請 GPT Work 用 git 推上去。

## 修改題目

題庫由 `workflow/題目藍圖.xlsx` 產生。改題目會同時影響圖片清單、錄音清單和已收集成績的可比性，請不要直接改 `site/data/items.js`。
